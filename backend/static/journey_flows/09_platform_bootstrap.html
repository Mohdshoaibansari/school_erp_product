Flow 9 — Platform Bootstrap (Full E2E)

← Back to all flows
This flow: Combines Flow 1 + Flow 2 into a single end-to-end bootstrap using the new backend APIs. From zero state to a fully operating school with an admin user. No Supabase Admin API for Director bootstrap — uses POST /api/v1/platform/clients/{id}/users + /api/auth/activate. Useful for demos and full regression.
Prerequisites: Backend running. Platform owner user exists in Supabase Auth. No SUPABASE_SERVICE_ROLE_KEY needed — all activation uses the backend /api/auth/activate endpoint.

Steps

This flow uses a different client name ("Sunrise International") so you can run it independently.
1Platform Owner Login
2Create Client — Sunrise International
3Activate Client
4Bootstrap Director via Backend API
Single API call creates Supabase Auth user + client_user row + role. Returns user_id and invite_url. No Supabase Admin API needed.
POST /api/v1/platform/clients/$BOOT_CLIENT_ID/users Authorization: Bearer $BOOT_PLATFORM_TOKEN body: { "email":"director@sunrise.edu", "name":"Sunrise Director", "role_id":"$LOOKUP.roles.client_director", "user_category_id":"$LOOKUP.user-categories.Executive Leadership" }
Expected: 201 with user_id, invite_url. Uses lookups fetched in Step 1.
5Extract + Activate Director
Parse invite token from invite URL, then call activate to set password.
Director lifecycle: invited→active via POST /api/auth/activate.
6Director Login
7Get Institution Type
8Create + Activate Institution
9Create Admin User + Activate
Expected: 200 with {"message":"...", "user_tier":"institution", "client_slug":"sunrise"}. No Supabase Admin API needed — pure backend activation.
10Admin Login — Verify
✅ Flow 9 complete. Full bootstrap from zero to a working school with an admin user. Director bootstrapped via POST /api/v1/platform/clients/{id}/users + /api/auth/activate. Sunrise International is now fully operational. Use the BOOT_* env vars to continue testing flows for this client.
