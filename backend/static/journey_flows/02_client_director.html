Flow 2 — Client Director Journey

← Back to all flows
This flow: Client Director logs in → creates institution → activates it → creates institute admin, teacher, and student users. Assumes Flow 1 (Platform Owner Onboarding) was completed and the env vars are stored.
Prerequisites: Run Flow 1 first. Stored vars required: DIRECTOR_TOKEN, CLIENT_SLUG, CLIENT_ID. Also set SUPABASE_SERVICE_ROLE_KEY on the index page.

Steps

1Login as Client Director
Login as the Director created in Flow 1. Uses Host header = client slug.
If Host header is dropped, login still works — middleware falls back to app_user lookup.
2List institution types (lookup)
Get available institution types to use when creating the school.
3Create Institution (School)
Create "Greenwood High School" under this client. Starts in onboarding state.
4Activate Institution (onboarding → active)

Create Users

All users are created inside this institution. Each new user requires: (1) create in app_user via our API, (2) set password in Supabase Auth, (3) activate lifecycle. The Director's API call auto-creates the Supabase Auth user too.
5Create Institute Admin
Institution-scoped admin. Manages one school.
6Assign Admin Role
Role Admin id: 70343690-695e-46a0-992c-c6eed7fb0c57
7Activate Admin (set password)
8Activate Admin (lifecycle)
9Create Teacher
10Assign Teacher Role + Activate
11Create Student
12Assign Student Role + Activate
13Verify — List all users
Should show Director, Admin, Teacher, Student — all in this client only.
✅ Flow 2 complete. You now have:
  • INST_ID — Greenwood High School (active)
  • ADMIN_ID — Institute Admin (admin@greenwoodhigh.com / Admin@123)
  • TEACHER_ID — Teacher (teacher@greenwoodhigh.com / Teacher@123)
  • STUDENT_ID — Student (student@greenwoodhigh.com / Student@123)
Continue to Flow 3 — Institute Admin, Flow 4 — Teacher, or Flow 5 — Student.
