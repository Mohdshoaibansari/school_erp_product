Flow 14 — Fees Module Journey

← Back to all flows
This flow: Client Director logs in → creates fee types → assigns fees to students → records payments → waives a fee → student views their own fee assignments. Covers the full Fees business module lifecycle.

All values (institution_id, user_ids, fee_type_id) come from API lookups or prior flows — nothing is hardcoded.
Prerequisites: Run Flow 1 + Flow 2 first. Stored vars required: DIRECTOR_TOKEN, CLIENT_SLUG, CLIENT_ID, INST_ID, STUDENT_ID.

Part A — Setup & Fee Type Creation

1Login as Client Director
Fresh login to ensure we have a valid token for fee operations.
POST /api/auth/login Host: $CLIENT_SLUG.localhost body: { "email":"$DIRECTOR_EMAIL", "password":"$DIRECTOR_PASSWORD" }
2Create Fee Type — Annual Tuition Fee
Creates a fee type scoped to the institution (from $INST_ID). default_amount is in the institution's currency.
POST /api/v1/fee-types Authorization: Bearer $DIRECTOR_TOKEN body: { "name":"Annual Tuition Fee", "description":"Full-year tuition", "default_amount":50000, "institution_id":"$INST_ID" }
3Create Fee Type — Sports Fee
Second fee type for annual sports activities.
POST /api/v1/fee-types Authorization: Bearer $DIRECTOR_TOKEN body: { "name":"Annual Sports Fee", "description":"Sports & activities", "default_amount":5000, "institution_id":"$INST_ID" }
4List All Fee Types
Verify both fee types are visible for this institution.
GET /api/v1/fee-types?institution_id=$INST_ID Authorization: Bearer $DIRECTOR_TOKEN
Should show at least Tuition Fee (₹50,000) and Sports Fee (₹5,000).

Part B — Fee Assignment & Payment

5Assign Tuition Fee to Student
Bulk-assign the tuition fee type to a student. user_ids is an array — supports assigning to multiple students at once. All IDs come from stored vars.
POST /api/v1/fee-assignments Authorization: Bearer $DIRECTOR_TOKEN body: { "fee_type_id":"$TUITION_FEE_TYPE_ID", "amount":50000, "due_date":"2026-09-30", "academic_term":"2026-2027", "user_ids":["$STUDENT_ID"], "notes":"Full year tuition" }
Returns an array of assignments. We extract the first (and only) assignment ID via 0.id.
6Assign Sports Fee to Student
Assign the sports fee separately. This one we'll waive later.
POST /api/v1/fee-assignments Authorization: Bearer $DIRECTOR_TOKEN body: { "fee_type_id":"$SPORTS_FEE_TYPE_ID", "amount":5000, "due_date":"2026-09-30", "academic_term":"2026-2027", "user_ids":["$STUDENT_ID"], "notes":"Sports activities fee" }
7List Fee Assignments for Student
Filter by user_id=$STUDENT_ID. Should show both tuition and sports assignments.
GET /api/v1/fee-assignments?user_id=$STUDENT_ID Authorization: Bearer $DIRECTOR_TOKEN
Both assignments should appear with status: "pending" and total_paid: "0.00".
8Record Partial Payment on Tuition Fee
Record a ₹30,000 payment against the tuition assignment. payment_method is a free-text field. All IDs from stored vars.
POST /api/v1/payments Authorization: Bearer $DIRECTOR_TOKEN body: { "fee_assignment_id":"$TUITION_ASSIGNMENT_ID", "amount":30000, "payment_method":"Bank Transfer", "reference_number":"NEFT-2026-001", "notes":"First installment" }
Payment should auto-update the assignment's total_paid and status (pending → partially_paid).
9Get Fee Assignment — Verify Balance
Fetch the tuition assignment to confirm total_paid=30000 and remaining balance.
GET /api/v1/fee-assignments/$TUITION_ASSIGNMENT_ID Authorization: Bearer $DIRECTOR_TOKEN
Should show amount: 50000, total_paid: 30000, status: "partially_paid".
10List Payments
List all payments for this student. Should show the ₹30,000 payment with receipt number.
GET /api/v1/payments?user_id=$STUDENT_ID Authorization: Bearer $DIRECTOR_TOKEN
Should include the receipt with receipt_number, amount: 30000, payment_method: "Bank Transfer".

Part C — Fee Waiver

11Waive the Sports Fee
Waive the ₹5,000 sports fee with a reason. Waiver is terminal — assignment moves to waived status.
POST /api/v1/fee-assignments/$SPORTS_ASSIGNMENT_ID/waive Authorization: Bearer $DIRECTOR_TOKEN body: { "reason":"Sports scholarship awarded" }
Assignment status should now be waived.
12Verify — List Student's Fee Assignments After Waiver
Final check: one partially_paid, one waived.
GET /api/v1/fee-assignments?user_id=$STUDENT_ID Authorization: Bearer $DIRECTOR_TOKEN
Tuition: partially_paid (₹30,000 / ₹50,000). Sports: waived.

Part D — Student View

13Student Login
Student logs in to view their own fee assignments (tenant + ownership scoped).
POST /api/auth/login Host: $CLIENT_SLUG.localhost body: { "email":"$STUDENT_EMAIL", "password":"$STUDENT_PASSWORD" }
14Student Views Own Fees
Student should see their own fee assignments — ownership-filtered, no other student's data.
GET /api/v1/fee-assignments?user_id=$STUDENT_ID Authorization: Bearer $STUDENT_TOKEN
Student sees only their own assignments. If fee_assignment.read permission allows self-access, both assignments should appear.
15Student Views Own Payments
Student should see the ₹30,000 payment recorded against their tuition.
GET /api/v1/payments?user_id=$STUDENT_ID Authorization: Bearer $STUDENT_TOKEN
Should show the payment with receipt number and amount.
✅ Flow 14 complete. Fees module lifecycle verified:
  • Fee types created (Tuition ₹50,000 + Sports ₹5,000)
  • Fees assigned to student (both types)
  • Partial payment recorded (₹30,000 via Bank Transfer)
  • Sports fee waived (scholarship)
  • Student views own fees and payments (ownership-scoped)
Stored: TUITION_FEE_TYPE_ID, SPORTS_FEE_TYPE_ID, TUITION_ASSIGNMENT_ID, SPORTS_ASSIGNMENT_ID, PAYMENT_ID.
