Flow 13 — Configuration Framework (C-08)

← Back to all flows
This flow: Tests the full C-08 Configuration Framework — key registry CRUD, value overrides with scope inheritance (Platform → Client → Institution), merge strategies (append_lists), deprecation, audit log, and authorization.

Real-world scenario: A school chain wants different attendance statuses, late fee policies, and homework submission rules for each school. The Platform Owner sets defaults, the Client Director overrides for their chain, and each Institute Admin fine-tunes for their school.
Prerequisites: Backend running on http://127.0.0.1:8000. Migrations 009 + 010 applied (21 seed keys). Platform Owner exists in Supabase Auth. Run Flow 2 first to create a Client + Institution + Client Director if you haven't already.

Part A — Platform Owner: Set Global Defaults

1Login as Platform Owner
No Host header — platform owner is client-independent.
POST /api/auth/login body: { "email":"admin@school-erp.com", "password":"Shoby@123" }
2List all 21 seed keys
Verify 21 keys across 7 categories (15 original + 6 from migration 010).
GET /api/v1/config/keys Authorization: Bearer $PLATFORM_TOKEN
Should return 21 keys. New keys include auth.jwtExpirySeconds, auth.inviteExpiryDays, auth.passwordResetRedirectUrl, homework.lateSubmissionPolicy, homework.closedStatusValues, platform.configDeprecatedHideDays.
3Set auth.jwtExpirySeconds = 7200 (2 hours)
Platform Owner changes JWT expiry from 1 hour to 2 hours globally. All institutions inherit this unless they override.
GET /api/v1/config/keys?key=auth.jwtExpirySeconds Authorization: Bearer $PLATFORM_TOKEN
PATCH /api/v1/config/keys/$JWT_KEY_ID Authorization: Bearer $PLATFORM_TOKEN body: { "default_value": 7200 }
All institutions now get 7200s (2h) JWT expiry unless overridden.
4Set auth.passwordResetRedirectUrl for production
Platform Owner sets the password reset URL to the production frontend.
GET /api/v1/config/keys?key=auth.passwordResetRedirectUrl Authorization: Bearer $PLATFORM_TOKEN
PATCH /api/v1/config/keys/$RESET_URL_KEY_ID Authorization: Bearer $PLATFORM_TOKEN body: { "default_value": "https://school-erp.com/reset-password" }
5Set homework.lateSubmissionPolicy = "submitted" (lenient)
Platform default: all submissions treated as on-time (no late penalty). Schools can override to "late" or "rejected".
GET /api/v1/config/keys?key=homework.lateSubmissionPolicy Authorization: Bearer $PLATFORM_TOKEN
Resolve default value GET /api/v1/config/resolve/homework.lateSubmissionPolicy Authorization: Bearer $PLATFORM_TOKEN
Default is "submitted" — all homework is treated as on-time. Schools can override to "late" (mark as late) or "rejected" (block after deadline).
6Verify auth.jwtExpirySeconds resolves to 7200
Confirm the platform default was updated.
GET /api/v1/config/resolve/auth.jwtExpirySeconds Authorization: Bearer $PLATFORM_TOKEN
Should return: {"resolved_value": 7200, "source_scope": "platform:default"}

Part B — Client Director: Override for School Chain

7Login as Client Director
Client Director manages all institutions under their client. Uses Host header for tenant resolution.
POST /api/auth/login body: { "email":"shoby.ansari586@gmail.com", "password":"Admin@123" } Host: meerutpublic.localhost
After this, use $CD_TOKEN with Host: meerutpublic.localhost for Client Director actions.
8Get the client ID for the school chain
Client Director needs the client_id to set client-scope overrides.
GET /api/v1/platform/clients Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost
Filters by CD_CLIENT_SLUG env var (default: meerutpublic). Change in the env panel to point at a different client.
9Get an institution ID for the school
Client Director lists institutions to get an institution_id for overrides.
GET /api/v1/institutions Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost
10Override attendance.statuses for the school chain
Client Director wants all schools in the chain to have ["present","absent","half_day","leave"].
Uses append_lists merge — adds to the platform default.
GET /api/v1/config/keys?key=attendance.statuses Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost
POST /api/v1/config/values Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost body: { "key_id":"$ATT_KEY_ID", "scope_type":"client", "scope_id":"$CLIENT_ID", "value":["half_day","leave"] }
With append_lists merge: platform ["present","absent"] + client ["half_day","leave"] = ["present","absent","half_day","leave"].
11Override homework.lateSubmissionPolicy = "late" for the chain
Client Director wants all schools to mark late submissions as "late" (not just "submitted").
POST /api/v1/config/values Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost body: { "key_id":"$LATE_POLICY_KEY_ID", "scope_type":"client", "scope_id":"$CLIENT_ID", "value":"late" }
All schools in this chain now mark late homework as "late" instead of "submitted".
12Resolve attendance.statuses for an institution (inherits client)
Resolve for a specific institution — should inherit the client override (append_lists).
GET /api/v1/config/resolve/attendance.statuses?institution_id=$INST_ID&client_id=$CLIENT_ID Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost
Should return: ["present","absent","half_day","leave"] (platform + client merged via append_lists).
13Resolve homework.lateSubmissionPolicy for an institution
Inherits the client override "late" (not the platform default "submitted").
GET /api/v1/config/resolve/homework.lateSubmissionPolicy?institution_id=$INST_ID&client_id=$CLIENT_ID Authorization: Bearer $CD_TOKEN Host: meerutpublic.localhost
Should return: {"resolved_value":"late", "source_scope":"client:$CLIENT_ID"}

Part C — Institute Admin: Fine-Tune for Their School

14Login as Institute Admin
Admin of a specific school. Uses Host header for tenant resolution.
POST /api/auth/login body: { "email":"admin@test-school.com", "password":"Admin@123" } Host: test-school.localhost
After this, use $ADMIN_TOKEN with Host: test-school.localhost for Institute Admin actions.
15Admin overrides homework.closedStatusValues for their school
This school wants to accept submissions even for "closed" homework (grace period).
Sets closedStatusValues = ["active", "closed"].
GET /api/v1/config/keys?key=homework.closedStatusValues Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
POST /api/v1/config/values Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost body: { "key_id":"$CLOSED_KEY_ID", "scope_type":"institution", "scope_id":"$ADMIN_INST_ID", "value":["active","closed"] }
This school can now submit homework even when status is "closed". Other schools still require "active".
16Admin overrides attendance.statuses for their school only
This school wants an extra status: "excused". Sets institution override to ["excused"].
With append_lists: platform ["present","absent"] + client ["half_day","leave"] + institution ["excused"] = all 5.
POST /api/v1/config/values Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost body: { "key_id":"$ATT_KEY_ID", "scope_type":"institution", "scope_id":"$ADMIN_INST_ID", "value":["excused"] }
append_lists merges: ["present","absent"] + ["half_day","leave"] + ["excused"] = ["present","absent","half_day","leave","excused"].
17Resolve attendance.statuses for this school (full chain)
Should show all 5 statuses: platform + client + institution merged via append_lists.
GET /api/v1/config/resolve/attendance.statuses?institution_id=$ADMIN_INST_ID Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
Should return: ["present","absent","half_day","leave","excused"] — all 3 scopes merged.
18Resolve homework.closedStatusValues for this school
Should return ["active","closed"] (institution override, not platform default).
GET /api/v1/config/resolve/homework.closedStatusValues?institution_id=$ADMIN_INST_ID Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
Should return: ["active","closed"] — institution override.

Part D — Scope Precedence & Fallback

19Resolve auth.jwtExpirySeconds (always platform default)
No institution or client override exists — falls back to platform default 7200.
GET /api/v1/config/resolve/auth.jwtExpirySeconds?institution_id=$ADMIN_INST_ID Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
Should return: {"resolved_value":7200, "source_scope":"platform:default"}
20Resolve auth.passwordResetRedirectUrl (platform default)
No override — falls back to platform default "https://school-erp.com/reset-password".
GET /api/v1/config/resolve/auth.passwordResetRedirectUrl Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
Should return: "https://school-erp.com/reset-password" | platform:default
21Resolve homework.lateSubmissionPolicy (client override)
This school's client set "late" — should inherit from client scope, not platform.
GET /api/v1/config/resolve/homework.lateSubmissionPolicy?institution_id=$ADMIN_INST_ID Authorization: Bearer $ADMIN_TOKEN Host: test-school.localhost
Should return: "late" | client:$CLIENT_ID (inherited from client scope, not platform).

Part E — Audit & Cleanup

22View audit log (all config changes)
Shows all config changes across all scopes — who changed what, when.
GET /api/v1/config/audit?page_size=15 Authorization: Bearer $PLATFORM_TOKEN
Should show: key_created (seeds), key_updated (PO changed defaults), value_created (CD overrides, Admin overrides).
23View audit for attendance.statuses only
Filter by key to see the chain of overrides for attendance statuses.
GET /api/v1/config/audit?key=attendance.statuses Authorization: Bearer $PLATFORM_TOKEN
24Cleanup: Delete institution attendance override
Remove the institution-specific "excused" status.
DELETE /api/v1/config/values/$INST_ATT_VALUE_ID Authorization: Bearer $PLATFORM_TOKEN
25Cleanup: Delete client attendance override
Remove the client-wide "half_day,leave" statuses.
DELETE /api/v1/config/values/$CLIENT_ATT_VALUE_ID Authorization: Bearer $PLATFORM_TOKEN
26Cleanup: Delete client lateSubmissionPolicy override
Remove the client-wide "late" policy.
DELETE /api/v1/config/values/$CLIENT_LATE_POLICY_VALUE_ID Authorization: Bearer $PLATFORM_TOKEN
27Cleanup: Delete institution homework.closedStatusValues override
Remove the institution-specific ["active","closed"] override.
DELETE /api/v1/config/values/$INST_CLOSED_VALUE_ID Authorization: Bearer $PLATFORM_TOKEN
28Verify: attendance.statuses back to platform default
After cleanup, should return ["present","absent"] (platform default only).
GET /api/v1/config/resolve/attendance.statuses Authorization: Bearer $PLATFORM_TOKEN
Should return: ["present","absent"] | platform:default
