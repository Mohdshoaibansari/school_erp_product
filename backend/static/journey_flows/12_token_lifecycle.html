Flow 12 — Token Lifecycle Cross-Cutting

← Back to all flows
This flow: Exercises the full token lifecycle for both Platform Owner and a normal Client Director — login → use access token → refresh → use new token → logout → verify old refresh fails.
Prerequisites: Run Flow 1 first. Stored vars: CLIENT_SLUG. Supabase signups enabled (so Platform Owner + Director accounts exist).

Platform Owner Token Lifecycle

1Platform Owner Login
Notice: Platform Owner's refresh_token is empty (D2 — platform owner gets a custom HS256 JWT, no Supabase refresh).
2Use Access Token — List Clients
3Platform Owner Refresh — should fail (empty refresh)
Expected: 401 — Platform Owner must re-login (custom JWT has no refresh).

Client Director Token Lifecycle

4Director Login
5Use Access Token — List Institutions
6Refresh Access Token
Returns a new access + refresh token pair.
7Use New Access Token
8Logout (revoke refresh)
9Try to use revoked refresh token — should fail
Expected: 401 Invalid or expired refresh token.
10Login with wrong password — should fail
Expected: 401 Invalid email or password.
✅ Flow 12 complete. Token lifecycle verified for both user types.
  • Platform Owner: custom HS256 JWT, no refresh
  • Normal User: Supabase JWT, refresh works, logout revokes
  • Revoked tokens cannot be reused
