Flow 11 — Error / Edge Cases Cross-Cutting

← Back to all flows
This flow: Verifies the system correctly rejects invalid input, expired/invalid JWTs, missing permissions, and FK violations. Each step expects a non-2xx response — the "✓ Expected failure" indicator means the system rejected correctly.
Prerequisites: Run Flow 1 + Flow 2 first. Stored vars: PLATFORM_TOKEN, DIRECTOR_TOKEN, STUDENT_TOKEN, INST_ID, CLIENT_SLUG.

Steps

1No Authorization header
Expected: 401 Invalid or expired JWT.
2Invalid JWT (garbage)
Expected: 401 Invalid or expired JWT.
3Student tries to create fee type (no permission)
Expected: 403 Permission denied.
4Director tries to access platform endpoint (no permission)
Director does not have client.create permission — should be blocked.
Expected: 403 Permission denied — Director has no client.create permission.
5Invalid UUID in path parameter
Expected: 422 with uuid_parsing validation error.
6Nonexistent institution (valid UUID but not found)
Expected: 404 Institution not found.
7Invalid lifecycle transition (active → prospective)
Expected: 400 — disallowed transition arc.
8Create user with duplicate email
Expected: 409 with {"error":"email_taken"} or 400 from Supabase.
9Missing required field (create client without slug)
Expected: 422 validation error — slug field required.
10Reserved slug rejected
Expected: 400 with {"error":"slug_reserved"}.
✅ Flow 11 complete. All error/edge cases verified — the system correctly rejects invalid input with appropriate HTTP status codes and meaningful error messages.
