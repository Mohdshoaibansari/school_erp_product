Flow 2 — Client Director Journey

← Back to all flows
This flow: Client Director logs in → creates institution → activates it → creates institute admin, teacher, and student users. Assumes Flow 1 (Platform Owner Onboarding) was completed and the env vars are stored.
Prerequisites: Run Flow 1 first. Stored vars required: DIRECTOR_TOKEN, CLIENT_SLUG, CLIENT_ID.

Steps

1Login as Client Director
Login as the Director created in Flow 1. Uses Host header = client slug.
If Host header is dropped, login still works — middleware falls back to app_user lookup.
2List institution types (lookup)
Get available institution types to use when creating the school.
3Create Institution (School)
Create "$INST_NAME" under this client. Starts in onboarding state.
4Activate Institution (onboarding → active)

Create Users

All users are created inside this institution via POST /api/v1/users (backend API). Each starts in invited state. The response now includes {user, invite_url} — extract the token from invite_url and call POST /api/auth/activate to set password + activate. No Supabase Admin API needed — pure backend API.
5Create Institute Admin
Institution-scoped admin. Manages one school.
6Assign Admin Role
Role Admin resolved from /api/v1/lookups/roles at runtime.
7Extract Invite Token + Activate Admin
Extract the invite JWT from the invite URL, then call the backend activate endpoint. This sets the password AND transitions invited→active in one call — no Supabase Admin API needed.
Expected: 200 with {"message":"...", "user_id":"...", "user_tier":"institution", "client_slug":"$CLIENT_SLUG"}. No more invited→pending→active two-step transition — activate handles it all.
8Create Teacher
9Assign Teacher Role + Activate
10Create Student
11Assign Student Role + Activate
12Verify — List all users
Should show Director, Admin, Teacher, Student — all in this client only.
✅ Flow 2 complete. You now have:
  • INST_ID — $INST_NAME (active)
  • ADMIN_ID — Institute Admin ($ADMIN_EMAIL / $ADMIN_PASSWORD)
  • TEACHER_ID — Teacher ($TEACHER_EMAIL / $TEACHER_PASSWORD)
  • STUDENT_ID — Student ($STUDENT_EMAIL / $STUDENT_PASSWORD)
Continue to Flow 3 — Institute Admin, Flow 4 — Teacher, or Flow 5 — Student.
